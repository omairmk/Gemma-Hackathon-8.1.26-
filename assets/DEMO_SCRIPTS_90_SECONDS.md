# Exact 90-second demo scripts

Run only the script for the build that has passed its recorded gate(s). Bracketed phrases are spoken only when supported by visible evidence. Before rehearsing, replace every bracketed phrase with evidence-backed wording or delete it. Do not substitute claims.

## iPhone — GITimeline (90 seconds)

| Time | Action | Say |
|---|---|---|
| 0–10 | Show the New Entry tab and documentation-only badge. | “GITimeline is a documentation tool. It is not diagnosis or medical advice.” |
| 10–22 | Select the prepared synthetic prop from Photos. | “I’ll add a synthetic demonstration image. A photo is required; symptoms and a note are optional.” |
| 22–33 | Open Symptoms and context; set one optional value and/or note. | “These are user-reported context fields. They do not go into the image-model prompt.” |
| 33–48 | Tap Analyze; show progress, then the labeled review rows. | “The app returns structured, neutral visual observations for review—no generated medical narrative.” |
| 48–58 | Edit one labeled observation. | “The user can correct every AI-assisted field before it is saved.” |
| 58–70 | Tap Save Reviewed Entry; switch to History and open the card. | “Saving records the reviewed entry. The detail view keeps the user’s report and the reviewed observations distinct.” |
| 70–82 | Show Detail attribution and model footnote if present. | “This entry is labeled with its review provenance. Missing optional fields remain ‘Not recorded.’” |
| 82–90 | Show the visible Airplane Mode evidence only if the device gate just passed; otherwise end on the documentation-only badge. | **If verified:** “[This run was demonstrated in Airplane Mode; exact evidence reference: ___].” **Otherwise:** “We are not making an offline or on-device claim in this demo.” |

## Mac fallback — GI Journal (90 seconds)

| Time | Action | Say |
|---|---|---|
| 0–10 | Show the running app and its documentation-only boundary. | “GI Journal is a documentation prototype, not a diagnostic or treatment tool.” |
| 10–22 | Select the prepared synthetic fixture. | “This demo uses a synthetic fixture; no real patient image is needed.” |
| 22–38 | Start the analysis path and show only the completed UI/output actually available. | “The model is used for [verified deployment scope and exact function].” |
| 38–52 | Show structured result and any validation/review UI. | “Outputs are constrained to neutral structured observations and require human review before saving.” |
| 52–65 | Edit/review and save, if that completed flow exists. | “The saved record preserves the reviewed result and its provenance.” |
| 65–78 | Show history/detail or the strongest finished, visible feature. | “This is the completed workflow we can demonstrate today.” |
| 78–90 | Show recorded offline/loopback evidence only if it was actually run. | **If verified:** “[This behavior was tested with exact test/evidence: ___].” **Otherwise:** “We are not making an offline or local-processing claim in this demo.” |

Never say “HIPAA-compliant,” “medical-grade,” “accurate,” “safe,” “private,” “offline,” or “on-device” unless the specific claim is proven and permitted by the event rules.

If privacy/backup behavior is discussed after the iPhone demo, use this exact sentence only after verifying it matches the final app: “The app sends no journal data to its own server and provides no app-managed sync. iOS may include journal data in your device backup, depending on your settings.”
